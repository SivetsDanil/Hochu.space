# TabChat

Мессенджер в духе Telegram, но с вкладками внутри чатов и голосовыми каналами как в Discord.
`TabChat-Server.exe` поднимает сервер и сам открывает туннель в интернет: в его окне — постоянная ссылка для друзей.
Заходить можно через приложение `TabChat.exe` (отдельное окно, код клиента внутри приложения) или просто в браузере по ссылке.
Переписка, файлы и звонки защищены **сквозным шифрованием**.

## Возможности

- **Аккаунты.** Регистрация с уникальным `@username`, вход по паролю (сам пароль на сервер не уходит), профиль: аватар, имя, «о себе», цвет.
  В одном браузере можно держать несколько аккаунтов и переключаться между ними.
- **Чаты.** Личные переписки, группы и «Избранное».
  - Новых людей можно искать по имени и `@username`.
  - В группу зовут по ссылке-приглашению `/join/…`.
  - Роли: владелец, админ и участник. Админ может удалить участника, владелец назначает админов.
- **Вкладки в группах.** Текстовые вкладки работают как темы, у каждой свой счётчик непрочитанных.
  Голосовые каналы — тоже вкладки. Админы создают, переименовывают и удаляют вкладки.
- **Сообщения.**
  - Ответы, редактирование, удаление и реакции.
  - Разметка: `**жирный**`, `__курсив__`, `~~зачёркнутый~~`, `` `код` ``, ```` ```блок``` ````, ссылки и @упоминания.
  - Отметки о прочтении ✓✓, «печатает…», разделитель непрочитанных, черновики для каждой вкладки.
  - ↑ в пустом поле открывает правку последнего своего сообщения.
- **Голосовые сообщения.** Запись с живой волной. При воспроизведении видна волна и прогресс, есть скорость 1x/1.5x/2x.
  Следующее голосовое запускается само.
- **Кружки.** Видео до 60 секунд в квадратном кадре. Камеру можно переключать прямо во время записи.
- **Фото и файлы.** Перетаскивание, вставка из буфера, подпись. Большие фото сжимаются, можно отправить и «без сжатия».
  Видео и аудио из файлов проигрываются прямо в чате.
- **Голос и видео.** Голосовые каналы в группах: индикатор речи, выключение микрофона и звука.
  В личке есть звонки и видеозвонки со входящим вызовом, рингтоном и таймером.
  - В любом голосе можно включить камеру или демонстрацию экрана (на компьютере).
  - Участники с видео показываются плитками; плитку можно развернуть кликом или открыть на весь экран.
  - На телефоне камеру можно переключать между фронтальной и основной.
- **Карта групп.** Админ отмечает группу на карте: ищет адрес или двигает карту под метку.
  Остальные видят группы на карте OpenStreetMap, ищут их по названию и адресу и подают заявку на вступление с парой слов о себе.
  Админам приходит уведомление, над лентой появляется плашка с заявками, а принять или отклонить их можно в один клик.
  После отказа новую заявку в ту же группу можно подать через 12 часов.
- **Сквозное шифрование** — подробнее ниже.
- **Постоянная ссылка в интернет без настройки.** При запуске exe сам открывает бесплатный туннель через srv.us (по встроенному в Windows ssh). Ссылку он печатает в консоли, копирует в буфер обмена и показывает в приложении.
  Адрес выводится из ключа в папке `data`, поэтому он не меняется между запусками и печатается сразу. Если srv.us недоступен, чат сам переходит на запасной localhost.run.
  Для постоянного и быстрого адреса есть свой туннель, как ngrok или tuna: см. [tunnel/README.md](tunnel/README.md).
- **Остальное.**
  - Онлайн-статусы и «был(а) в сети…».
  - Уведомления на рабочем столе и звуки.
  - Тёмная и светлая темы, мобильная вёрстка.
  - Список устройств с завершением сеансов.
  - Можно установить как приложение (PWA).

## Сквозное шифрование

Сервер хранит и пересылает только шифротекст. Ключи создаются и хранятся в браузере.

- **Пароль не покидает браузер.** PBKDF2 (310 000 итераций) выводит из него два ключа:
  - `auth` — его сервер проверяет при входе вместо пароля;
  - ключ, которым зашифрована резервная копия ваших личных ключей. Его сервер не видит никогда.
- **Личные ключи** создаются в браузере при регистрации: ECDH P-256 для обмена ключами и ECDSA P-256 для подписи.
  На сервер уходят открытые ключи и зашифрованная паролем копия закрытых — она нужна, чтобы войти с другого устройства.
- **У каждого чата свой ключ AES-256.** Он «завёрнут» отдельно для каждого участника через ECDH.
  Новичкам ключ передаёт кто-то из участников в сети: он приходит автоматически, и новичок видит историю.
  Когда кто-то выходит или его удаляют, начинается новая «эпоха» ключа, и написанное после этого ушедший прочитать не сможет.
- **Каждое сообщение** — это AES-256-GCM с привязкой к чату, вкладке, отправителю и типу сообщения, плюс подпись ECDSA отправителя.
  Подделать сообщение от чужого имени не может даже участник группы.
- **Файлы, голосовые и кружки** шифруются своим ключом до загрузки. Имя файла, длительность и волна голосового лежат внутри шифротекста.
- **Звонки** идут напрямую между браузерами и шифруются WebRTC (DTLS-SRTP). Кроме этого, DTLS-отпечатки в SDP подписываются личными ключами — сервер не может незаметно встать посередине.
  В звонке видны 4 эмодзи: у собеседника должны быть такие же.
- **Код безопасности.** В профиле собеседника есть 8 эмодзи и 60 цифр для сверки при встрече.
- **Закреплённые ключи.** Ключи собеседника запоминаются при первой встрече, а законно они не меняются никогда.
  Если сервер выдаст другой ключ, клиент им не пользуется: не передаёт по нему ключи чатов и не принимает его подписи. Новый ключ принимается, только когда вы сверите код безопасности.
- **Повтор и подмена.** Сообщение нельзя повторить под новым номером, перенести в другой чат или вкладку, выдать за другой тип или за другого автора — такое помечается ⚠️.
- **Страница и вход.** Политика безопасности (CSP) разрешает только скрипты самого TabChat. После 8 неудачных входов в аккаунт за 15 минут вход в него ставится на паузу.

**Что видит сервер:** кто с кем переписывается и когда, размеры сообщений, названия и аватары групп, профили, реакции.
Группы, отмеченные на карте, видны всем пользователям сервера: название, описание, аватар, адрес и число участников. Переписка в них при этом остаётся зашифрованной.
Поиск адресов идёт через сервер к Nominatim (OpenStreetMap), а картинки карты браузер берёт прямо с серверов OpenStreetMap.

**Чего нет:**
- *Прямой секретности* (как у Signal): если украсть личный ключ, можно расшифровать прошлую переписку.
- *Восстановления пароля*: без пароля переписку на новом устройстве не открыть.
- *Защиты от «призрачного участника»:* состав группы ведёт сервер. Злонамеренный сервер может добавить в группу своего участника, и клиенты передадут ему ключ, как любому новичку. Это видно в списке участников и в системном сообщении. Так же устроены и большие мессенджеры с серверными группами.
- *Защиты метаданных:* время отправки ставит сервер. В опросах сервер видит, кто выбрал какой по счёту вариант, но не видит текст вопроса и вариантов.
- *В браузере — защиты от сервера как раздатчика программы:* веб-версия загружает код клиента с сервера, поэтому доверять нужно тому, кто его запускает (и туннелю: HTTPS у srv.us и localhost.run расшифровывается на их стороне).
  **Приложение `TabChat.exe` это закрывает:** код клиента встроен в него, а с сервера приходят только данные. Сервер и туннель видят сообщения и файлы только зашифрованными и не могут подменить код.

Сообщения, отправленные до включения шифрования, остаются как были и помечены 🔓.
Старые аккаунты переходят на новую схему при первом входе или вводе пароля.

## Запуск

- **Сервер:** `release\TabChat-Server.exe`. Откроется окно:
  - «Ссылка для друзей» — постоянный адрес `https://….srv.us`, он работает из любой сети. При запуске он уже скопирован в буфер обмена, рядом кнопки «Копировать» и «Открыть в браузере».
  - «Открыть TabChat» — приложение на этом же компьютере.
  - Адреса для домашней сети, сколько человек онлайн, журнал и папка с данными.
  - Закрыть окно — остановить сервер. Второй сервер с той же папкой данных не запустится: вместо этого окно покажет ошибку.
- **Приложение:** `release\TabChat.exe`. Его можно дать друзьям или скачать прямо с сервера: в веб-версии на Windows в меню есть пункт «Приложение для Windows».
  - При первом запуске вставьте ссылку на сервер или приглашение в группу. Если сервер запущен на этом же компьютере, хватит кнопки «Этот компьютер».
  - Окно открывается через Edge (или Chrome) в режиме приложения, без адресной строки. Свой профиль хранится в `%LOCALAPPDATA%\TabChat\Browser`, а список серверов — в `%APPDATA%\TabChat`.
  - Серверов может быть несколько: «Меню → Сервер» открывает их список. У каждого сервера свои аккаунты и ключи.
  - Приложение закрывается вместе с последним своим окном. Ссылку можно передать и при запуске: `TabChat.exe https://….srv.us/join/код`.
- **Браузер** тоже работает: по той же ссылке с телефона или компьютера. На телефоне TabChat можно установить как приложение (PWA).
- **Туннель в интернет:**
  - По умолчанию он бесплатный, через srv.us. Настраивать ничего не нужно, адрес постоянный.
    Серверы сервиса в США, поэтому каждый запрос занимает около полсекунды. Чтобы это не мешало, код страницы кэшируется, а сообщения появляются сразу, не дожидаясь сервера.
    Если связь с туннелем рвётся, он переподключается сам, а клиенты подхватывают соединение без перезагрузки.
  - Чтобы получить новый постоянный адрес, удалите `data\tunnel_key`.
  - Свой relay даёт адрес поближе, полную скорость и TURN для звонков. Запустите сервер один раз с ключом, дальше он подключается сам:
    ```
    TabChat-Server.exe --tunnel tabtunnel://секрет@адрес-relay
    ```
  - Вернуться к бесплатному: `--tunnel free`.
  - Выключить насовсем: `--tunnel-off`. Не поднимать один раз: `--no-tunnel`.
  - Желаемое имя на relay: `--tunnel-name`.
- **Утилита TabTunnel:** `release\TabTunnel.exe` открывает в интернет любой локальный порт через тот же relay.
- **Из исходников:**
  - сервер в консоли (например, на VPS или Linux): `.venv\Scripts\python server.py`, окно — с флагом `--gui`;
  - приложение: `.venv\Scripts\python client.py [ссылка]`;
  - флаги сервера: `--port 8080`, `--https-port 8443`, `--data папка`, `--no-browser`. Если порт занят, берётся следующий свободный.
- **Сборка всех exe:** `build.bat`.
- **Тесты:**
  - сервер, шифрование, карта и прокси приложения: `.venv\Scripts\python tests\smoke_test.py`;
  - туннель: `.venv\Scripts\python tunnel\tests\test_tunnel.py`.

Все данные сервера лежат в папке `data\` рядом с `TabChat-Server.exe`: база `tabchat.db`, зашифрованные файлы `media\`, сертификат, настройки туннеля.
Чтобы перенести мессенджер на другой компьютер вместе с перепиской, скопируйте программу и эту папку.

## Как зайти с других устройств

- **Приложением в домашней сети** — по адресу `http://<IP-компьютера>:8080`, он есть в окне сервера. Приложению https не нужен: микрофон и шифрование работают и так.
- **Браузером в домашней сети** — по ссылке `https://<IP-компьютера>:8443`, она тоже есть в окне сервера.
  - Шифрование и микрофон в браузере работают только по https или на localhost, поэтому сервер сам создаёт сертификат.
  - Сертификат самоподписанный, и при первом входе браузер предупредит: нажмите «Дополнительно» → «Перейти на сайт».
- **Из интернета** — по ссылке «Из интернета», которую программа печатает при запуске. Это адрес бесплатного туннеля или вашего relay. Сертификат там настоящий, поэтому предупреждений нет.
- При первом запуске Windows спросит про брандмауэр: разрешите доступ в частных сетях.

## Устройство

| Где | Что |
|---|---|
| `server.py` | TabChat Server: порты, HTTPS, туннель, блокировка папки данных; окно или консоль |
| `tabchat/server_gui.py` | окно сервера: ссылка для друзей, кнопки, онлайн, журнал |
| `client.py` | TabChat.exe: окно Edge/Chrome в режиме приложения, один экземпляр, выход с последним окном |
| `tabchat/appclient.py` | прокси приложения: встроенный клиент, `/api`, `/ws`, `/media` → сервер; список серверов, проверка версии |
| `tabchat/assets.py` | статика из памяти: gzip, версии файлов, карта импортов (общая для сервера и приложения) |
| `tabchat/version.py` | версия и номер протокола клиент ↔ сервер |
| `tabchat/db.py` | SQLite: пользователи и их открытые ключи, сессии, чаты, ключи чатов по эпохам, сообщения, файлы; миграции |
| `tabchat/hub.py` | WebSocket-хаб: RPC-методы, события, ключи, голосовые комнаты, звонки, TURN |
| `tabchat/web.py` | HTTP: регистрация и вход без пароля, загрузка и раздача файлов, страницы |
| `tabchat/security.py` | хэши для входа (PBKDF2) и токены сессий (в базе хранятся только хэши) |
| `tabchat/tunnel_link.py` | туннель при запуске: бесплатный (srv.us, запасной localhost.run, через ssh) или свой relay |
| `static/js/crypto.js` | всё сквозное шифрование (WebCrypto) |
| `static/js/map.js` | своя карта на тайлах OpenStreetMap: жесты, масштаб, метки с группировкой, без сторонних библиотек |
| `static/js/places.js` | экран карты групп, выбор места группы, заявки на вступление |
| `static/js/connect.js` | режим приложения: выбор сервера, «пульс» окна |
| `static/js/*` | остальной клиент на чистом JS (ES-модули), без сборки |
| `static/css/app.css` | стили, обе темы |
| `tunnel/` | TabTunnel: relay для VPS, клиент, утилита, установщик |
| `tests/smoke_test.py` | сквозная проверка API и протокола шифрования |

Голос и видео идут напрямую между браузерами (WebRTC mesh): каждый соединён с каждым.
Голосом комфортно до 6–8 человек в канале, с включёнными камерами — до 4–5 (каждый отправляет видео каждому).
У каждого соединения сразу есть видео-слот, поэтому камера и экран включаются без пересогласования (`replaceTrack`).

Если напрямую соединиться не удаётся (NAT провайдера), звонок идёт через TURN на вашем relay (`install.sh --turn`).
У бесплатного туннеля TURN нет, поэтому в редких сетях (например, у некоторых мобильных операторов) звонок может не соединиться.
Шифрование при этом остаётся сквозным: TURN пересылает только зашифрованные пакеты.
