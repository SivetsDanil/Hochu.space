# TabTunnel — свой туннель в интернет

Утилита открывает программу на домашнем компьютере (например, чат на `localhost:8080`) по ссылке из интернета. Это то же, что делают ngrok и tuna, только сервер свой.

## Как устроены ngrok и tuna

Домашний компьютер почти всегда сидит за NAT роутера, а часто ещё и за NAT провайдера (CGNAT). Из интернета к нему нельзя подключиться напрямую: у него нет публичного адреса, и роутер не знает, кому отдать входящее соединение. Зато **исходящие** соединения из дома работают всегда. На этом и построены все туннели:

```
 посетитель                        сервер с публичным IP                    ваш компьютер
 (браузер) ──HTTPS──▶  relay (ngrok.app / tuna.am / ваш VPS)  ◀──одно исходящее──  клиент туннеля ──▶ localhost:8080
                       │                                        соединение               │
                       └── заворачивает каждое входящее ─────▶ (WebSocket)  ───────▶ открывает
                           соединение в «поток» внутри                                 соединение
                           этого одного соединения                                     к программе
```

1. **Клиент** (`ngrok http 8080`, `tuna http 8080`) сам подключается к серверу сервиса и держит это соединение открытым. Обычно это TLS или WebSocket на порт 443, который пропускает любой фаервол.
2. **Сервер** (relay, edge) выдаёт клиенту публичное имя. На этом имени висят DNS-запись и сертификат вида `*.ngrok.app`.
3. Когда браузер открывает ссылку, relay принимает соединение и по имени в запросе (Host или SNI) понимает, какому клиенту оно предназначено. Затем он открывает новый **поток** внутри уже существующего соединения с этим клиентом. Много потоков в одном соединении — это мультиплексирование, как в HTTP/2 или yamux.
4. Клиент для каждого потока открывает соединение к `localhost:8080` и гоняет байты в обе стороны.

Платные функции этих сервисов — постоянные адреса, свои домены, панель запросов, защита паролем. Всё это надстройки над той же схемой. Главное, за что вы платите, — **сервер с публичным IP**. Без такой машины туннель не построить: кто-то в интернете должен принимать входящие соединения.

TabChat без настройки берёт такую машину взаймы — бесплатный сервис srv.us, а если он недоступен, localhost.run. К ним подключается встроенный в Windows `ssh -R`. srv.us выводит адрес из ssh-ключа, поэтому ссылка постоянная. Но серверы сервиса в США, так что каждый запрос из России идёт через океан. Свой relay ниже, поставленный поближе, даёт меньшую задержку, полную скорость и TURN для звонков.

## Как устроен TabTunnel

```
 браузер ──HTTPS──▶ Caddy :443 ──HTTP──▶ relay.py :7000 ══ WebSocket ══▶ клиент TabTunnel ──▶ TabChat :8080
                   (сертификат            (ваш VPS)        (одно соединение   (внутри TabChat.exe
                    Let's Encrypt)                          из дома наружу)    или TabTunnel.exe)
```

- **`relay/relay.py`** — сервер-ретранслятор. Ставится на любой VPS и работает только на стандартной библиотеке Python. Внутри у него свой минимальный WebSocket-сервер и мультиплексор потоков.
- **`relay/install.sh`** — установка одной командой. Ставит Caddy, который сам получает HTTPS-сертификаты, relay как службу systemd и, по желанию, TURN-сервер для звонков.
- **`tabtunnel/`** — клиент. Он встроен в TabChat (туннель поднимается сам при запуске) и в утилиту TabTunnel.
- **`app.py`** — утилита TabTunnel: окно с минимальным дизайном или консоль в духе `ngrok http 8080`.

### Протокол

Клиент подключается к `wss://relay/_tunnel` и отправляет `{"type":"hello","token":…,"name":…}`. В ответ приходит `{"type":"welcome","url":…}`.

Дальше идут бинарные кадры: `[1 байт тип][4 байта id потока][данные]`.

| Тип | Кто шлёт | Смысл |
|---|---|---|
| `OPEN` | relay | новый посетитель, открой соединение к локальной программе |
| `DATA` | обе стороны | байты потока |
| `WINDOW` | обе стороны | «я записал N байт, можешь слать ещё» — управление потоком, чтобы большая загрузка не съела память |
| `EOF` | обе стороны | данные в эту сторону кончились (полузакрытие, как в TCP) |
| `CLOSE` | обе стороны | оборвать поток |

Relay пересылает байты как есть и не разбирает HTTP. Поэтому через туннель работают WebSocket, большие загрузки, докачка и вообще любой протокол поверх TCP.

Режимов работы два:

- **Один туннель** (по умолчанию): всё, что пришло на адрес сервера, уходит единственному клиенту.
- **Много туннелей** (`--multi`): у каждого клиента своё имя, адрес вида `https://имя.домен`. Caddy выпускает сертификат для каждого имени на лету (on-demand TLS) и перед этим спрашивает у relay, подключён ли такой туннель.

## Как запустить у себя

Нужен любой VPS с Ubuntu или Debian и публичным IP. Хватает самого дешёвого тарифа: relay почти не нагружает процессор.

1. Скопируйте папку `tunnel/relay` на сервер и запустите установку. С Windows 10/11 это делается встроенными `scp` и `ssh`:
   ```
   scp -r tunnel\relay root@АДРЕС-СЕРВЕРА:/root/tabtunnel
   ssh root@АДРЕС-СЕРВЕРА "bash /root/tabtunnel/install.sh --turn"
   ```
   В конце установщик напечатает **ключ подключения** вида `tabtunnel://секрет@1-2-3-4.sslip.io`.
   - Домен покупать не нужно: `1-2-3-4.sslip.io` бесплатно указывает на IP `1.2.3.4`.
   - `--turn` добавляет TURN-сервер, чтобы звонки проходили через любой NAT.
2. Подключите чат. Это делается один раз, дальше туннель поднимается сам при каждом запуске:
   ```
   TabChat.exe --tunnel tabtunnel://секрет@1-2-3-4.sslip.io
   ```
   В консоли появится строка `Из интернета: https://…`, а ссылки-приглашения в чате начнут вести на этот адрес.
   - Вернуться к бесплатному туннелю: `--tunnel free`.
   - Выключить туннель: `--tunnel-off`.
   - Не поднимать туннель один раз: `--no-tunnel`.
3. Любую другую программу можно открыть через **TabTunnel.exe**: вставьте ключ, укажите порт и нажмите «Запустить».

### Проверить у себя без сервера

Relay можно запустить на этом же компьютере. Браузер Chrome сам понимает адреса `*.localhost`:

```
.venv\Scripts\python tunnel\relay\relay.py --listen 127.0.0.1 --port 7100 --token test --domain localhost --scheme http --url-port 7100
.venv\Scripts\python server.py --tunnel tabtunnel+ws://test@127.0.0.1:7100/chat
```

После этого чат откроется по адресу `http://chat.localhost:7100`, то есть через туннель.

Автотесты туннеля: `.venv\Scripts\python tunnel\tests\test_tunnel.py`.

## Безопасность

- **Ключ подключения — секрет.** Кто его знает, может подключить свой туннель к вашему relay (в режиме одного туннеля — подменить ваш). Ключ лежит в `/etc/tabtunnel/token`; поменяйте его и перезапустите `tabtunnel-relay`, если ключ утёк.
- **HTTPS.** Шифрование HTTPS заканчивается на Caddy, то есть на вашем же сервере. Переписку и звонки TabChat это не раскрывает: они защищены сквозным шифрованием, и сервер видит только шифротекст.
- **TURN** не пускает в частные сети сервера (`denied-peer-ip`). Пароли для него временные, их выдаёт TabChat на сутки.
